# Updating the Chatwoot catalog

`src/integrations/chatwoot/chatwoot-node-snapshot.json` is generated from the built
`@renatoascencio/n8n-nodes-chatwoot` package. It contains both node descriptions,
all operation and parameter definitions (including nested collections and display
conditions), and the three credential definitions. The runtime catalog derives
its resources, operations, trigger events and AI tool variant from this file.
Do not edit the snapshot by hand.

The current snapshot was generated from the published npm package
`@renatoascencio/n8n-nodes-chatwoot@0.9.0`
([source](https://github.com/serversmx/n8n-nodes-chatwoot)): two nodes, 39 resources,
269 operations and three credentials.

## 1. Regenerate the snapshot

Use the published tarball (or a fresh build of the tagged source; a stale `dist/`
produces a stale snapshot):

```sh
npm pack @renatoascencio/n8n-nodes-chatwoot@0.9.0 && tar xzf renatoascencio-n8n-nodes-chatwoot-0.9.0.tgz
NODE_PATH="$PWD/node_modules" npm run generate:chatwoot-catalog -- \
  --package /path/to/package \
  --version 0.9.0 \
  --source '@renatoascencio/n8n-nodes-chatwoot@0.9.0 (npm)'
```

The source label is provenance text, not an executable reference. The package's
dependencies, including `n8n-workflow`, must resolve from its own `node_modules` or
`NODE_PATH` (n8n-mcp's own `node_modules` works). The generator executes the compiled
node modules, so use a trusted package. It reads only the modules declared in
`package.json` under `n8n.nodes` and `n8n.credentials`, uses n8n-mcp's `NodeParser`,
and clears password-field defaults. No timestamps, machine paths or network requests
enter the snapshot.

Repeat the same command with `--check` to compare the generated bytes against the
checked-in file without writing it. This exits unsuccessfully on drift or a missing
snapshot. `--out /path/to/snapshot.json` selects another existing output directory.

## 2. Register the nodes in `data/nodes.db`

The Docker image copies the checked-in `data/nodes.db`, and `search_nodes` /
`get_node` read from it, so the catalog alone is not enough: after regenerating the
snapshot, register the nodes and commit the database too.

```sh
npm run build && npm run register:chatwoot   # NODE_DB_PATH defaults to ./data/nodes.db
```

The database uses FTS5, so this needs a working `better-sqlite3` build (installing
with `--ignore-scripts` leaves it uncompiled). If the host cannot build it, run the
steps in a `node:20` container with the repository mounted:
`npm ci --legacy-peer-deps && npm run build && npm run register:chatwoot`.
Expect `@renatoascencio/n8n-nodes-chatwoot.chatwoot`, `.chatwootTool` and
`.chatwootTrigger` rows.

## 3. Verify

```sh
npx tsc --noEmit
npx vitest run tests/unit/chatwoot tests/handlers-chatwoot.test.ts \
  tests/chatwoot-connection-validator.test.ts \
  tests/unit/services/workflow-validator-chatwoot-catalog.test.ts --coverage.enabled=false
```

Review the snapshot diff along with template and validation tests on each release.
The webhook payload shapes in `chatwoot-node-catalog.ts` are maintained separately
from Chatwoot's server source (currently 4.18.0); they are not generated by the node
package. New events may require updating these shapes and the template tests.
