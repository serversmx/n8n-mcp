# Updating the Chatwoot catalog

`src/integrations/chatwoot/chatwoot-node-snapshot.json` is generated from the built
`@renatoascencio/n8n-nodes-chatwoot` package. It contains both node descriptions,
all operation and parameter definitions (including nested collections and display
conditions), and the three credential definitions. The runtime catalog derives
its resources, operations, trigger events and AI tool variant from this file.
Do not edit the snapshot by hand.

The current snapshot uses branch `feat/v0.9.0`, commit
`9166f80b6f22edfc44e8a95b6bc5d2b56247f365` **plus its captured working-tree changes**, of
[n8n-nodes-chatwoot](https://github.com/RenatoAscencio/n8n-nodes-chatwoot).
The source capture has SHA-256
`61b7790e810a5eb39bb1bc0fe64fe1fe265369a95500ba6837c648324b74f492`.
It hashes all files in `nodes/` and `credentials/`, plus `package.json` and
`tsconfig.json`, in sorted relative-path order, feeding each UTF-8 path, a NUL byte,
its file bytes and another NUL byte into SHA-256. Reproducing this snapshot requires
those working-tree changes; the commit alone produces the earlier 266-operation
catalog. The captured source has 269 operations and the additional trigger raw-text
option. Once these changes are committed, update the provenance to that commit.
That commit's package manifest still says `0.8.3`, so the commands below explicitly
label the intended `0.9.0` release. The override does not select a release or fetch
different code: always build the intended source first. After the package version
is bumped, omit `--version` to use its manifest version.

Build the node package in its own checkout (`npm ci` if dependencies are missing,
then `npm run build`). A stale `dist/` produces a stale snapshot. From the n8n-mcp
root, using the freshly built package root:

```sh
npm run generate:chatwoot-catalog -- \
  --package /path/to/n8n-nodes-chatwoot \
  --version 0.9.0 \
  --source 'n8n-nodes-chatwoot feat/v0.9.0@9166f80+worktree.sha256:61b7790e810a5eb39bb1bc0fe64fe1fe265369a95500ba6837c648324b74f492'
```

The source label is provenance text, not an executable git reference. Update it to
the exact revision when regenerating for another release. The package's dependencies,
including `n8n-workflow`, must resolve from its own `node_modules` or `NODE_PATH`.
The generator executes the compiled node modules, so use a trusted local build.
It reads only the modules declared in `package.json` under `n8n.nodes` and
`n8n.credentials`, uses n8n-mcp's `NodeParser`, and clears password-field defaults.
No timestamps, machine paths or network requests enter the snapshot.

Repeat the same command with `--check` to compare the generated bytes against the
checked-in file without writing it. This exits unsuccessfully on drift or a missing
snapshot. `--out /path/to/snapshot.json` selects another existing output directory
for either generation or checking. For the captured source, expect two nodes,
39 resources, 269 operations and three credentials.

```sh
npm run generate:chatwoot-catalog -- \
  --package /path/to/n8n-nodes-chatwoot \
  --version 0.9.0 \
  --source 'n8n-nodes-chatwoot feat/v0.9.0@9166f80+worktree.sha256:61b7790e810a5eb39bb1bc0fe64fe1fe265369a95500ba6837c648324b74f492' --check
npx tsc --noEmit
npx vitest run tests/unit/chatwoot --coverage.enabled=false
```

Review the snapshot diff along with template and validation tests on each release.
The webhook payload shapes in `chatwoot-node-catalog.ts` are maintained separately
from Chatwoot's server source (currently 4.18.0); they are not generated by the node
package. New events may require updating these shapes and the template tests.
